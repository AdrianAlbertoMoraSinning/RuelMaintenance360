# Supervisor acceptance gates observation AI memory

Every observation requires explicit acceptance by its assigned active supervisor before its text becomes searchable AI evidence. Submission, triage, a linked WO, closure, or CEO visibility alone do not grant admission. The supervisor uses “Accept observation for AI memory” with a review note. Operators cannot self-approve. The server records the accepting person, timestamp and immutable source snapshot; existing observations are not retroactively approved.

A private RLS-protected acceptance history and security-invoker view expose only current accepted snapshots within the caller’s existing observation access. Content/context changes and information-requested/rejected states revoke current admission. Resubmission alone does not restore it. Another supervisor acceptance is required. Training/MOC reports and assets cannot enter real memory. Pending safety reports continue their normal safety workflow; AI acceptance is not safety clearance or work authorization.

Accepted snapshots receive a full-text search index automatically. Technical Assistant retrieves relevant accepted reports for the selected asset, including accepted unit-wide reports without an asset. Citations retain observation number, source ID and acceptance time. It reads only the accepted description/resolution snapshot and acceptance note; unreviewed comments or subsequent edits do not enter automatically. Supervisor acceptance validates a report for use as history, not a confirmed diagnosis or demonstrated repair success.

The Edge Function reconstructs evidence from caller-authorized database rows rather than trusting browser-supplied content. It rechecks current observation acceptance, excludes WOs derived from unaccepted observations, and blocks if verification fails. Manual and WO citations are reconstructed from their source IDs. The frontend also uses the gated view for its extractive fallback, refreshes acceptance before each query, and adopts the backend’s citation order for AI answers. Existing AI provider credentials/model configuration remain required for generated answers; extractive evidence remains available without them.

Validation: database transaction covers unreviewed exclusion, reporter self-approval denial, unassigned CEO denial, assigned supervisor admission, idempotency, edited-text revocation, return/rejection/resubmission behavior, MOC exclusion, no client write/anon execution, unrelated operator isolation, and supervisor visibility. All fixtures roll back. Three local retrieval tests cover fabricated browser sources, unaccepted WO propagation and verification failures. Seventeen existing Auth/invitation tests and the production build pass. No actual operator observation was accepted as part of deployment.

# Dispatch quantity variance and performance ranges — 0.3.12

Programmed order quantity is retained as the baseline. Planned trip totals and actual load quantities may be higher or lower. Plan delivery permits an actual quantity different from its selected trip and offers an explicit Additional delivery beyond the plan option. Actual quantities can be adjusted with a reason while scheduled or ready, before departure. Existing planned quantities remain in the logistics history. Only authorized unit managers can perform these changes.

Programmed vs actual dispatch shows programmed, dispatched, delivered and difference totals. Close dispatch order accepts either positive or negative variance, requires a reason when quantities differ, and records actor, server timestamp, programmed/actual totals, variance and cancellation count. At least one delivery must be completed, with no ready or travelling loads. Closure cancels only scheduled unproduced loads. Receipts and signatures remain separate. Exact-quantity automatic completion remains available only when every assigned load is finished and every planned trip is completed; variance requires explicit closure. Requests check the reviewed totals and use stable identifiers to prevent duplicate audit entries on retry.

Business Unit Performance uses inclusive From and To activity dates in America/Edmonton, defaulting to month to date. Produced, dispatched and delivered quantities use their respective milestone dates, retain units of measure and respect unit scope. Fleet completions and hours use completion date. Pending, delayed and active counts explicitly show current state. Empty and reversed ranges do not display misleading totals.

Mobile Concrete Fleet operations, drivers, assets and operational references now belong to Peace River Concrete Plant. The old unit is inactive and retained for historical identity. Both inventory locations and warehouses retain their IDs; duplicate location names receive a Fleet prefix. Existing plant access is preserved, incoming operational access is moved, and global managers retain global visibility without redundant unit assignments. Truck TRK-131 is assigned to Olly as primary responsible person. Vehicle selectors exclude stationary plant equipment.

Administration uses the existing protected service-only lifecycle RPC for preflight and commit. It checks reporting responsibilities before changing Auth, restores previous ban status if commit fails, and supports named user removal with retained history. Removed profiles leave the normal directory; no accounts are removed automatically. Existing lifecycle database migrations were recovered from migration history to keep source aligned with production.

Validation: production UI/model tests, complete JavaScript suite, TypeScript/Vite build, rollback-only database suites for under/over quantities, logistics, manual milestones, tracking and user lifecycle. No real dispatch was closed and no existing user was deactivated or removed by QA.

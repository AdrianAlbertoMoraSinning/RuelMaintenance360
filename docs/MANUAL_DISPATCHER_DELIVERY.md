# Manual delivery milestones · 0.3.10

Authorized managers can record confirmed driver reports from the office while the driver's personal app is unavailable. Open the order, then the load card's Manual delivery controls. Ready loads offer Mark departed; departed loads offer Mark arrived; arrived loads offer Mark left site; once the exit is saved, Complete delivery becomes available. A driver-completed load without a site exit can still receive its separate manual exit record. Cancelled, unready and fully completed/exited loads have no further action.

Each click asks for confirmation, records the signed-in manager and current server time, uses a stable request identifier for retries and marks its source as dispatcher. It updates the existing customer tracking and sends an in-app notification to the order creator, dispatcher and assigned driver according to the established routing. The server enforces manager authority, actor binding, chronological milestones and the existing driver/vehicle occupancy checks. No app activation, driver impersonation or geofence bypass is required.

The existing driver and GPS flows remain available. A later driver acknowledgment of a dispatcher-recorded milestone does not duplicate the event. Manager completion requires prior recorded jobsite exit; the driver's existing ability to finish service before physically leaving remains unchanged. The last completed quantity closes the order. Completion never creates customer acceptance or a signature; the receipt remains pending unless actually captured.

Tests cover visible next actions, cancellation of confirmations, identity and stable retry payloads, manager-only APIs, forged actors, out-of-sequence calls, timestamps, customer tracking, all creator notifications, multi-load order closure, duplicate prevention, late driver acknowledgments and receipt separation. Database tests use a dedicated rollback-only QA vehicle and an available training driver, and do not progress real orders.

# Optional drawn signatures - release 0.3.4

Open a saved observation (Open review / report history) or a My To-do task. The Signatures · optional section offers Add my signature to eligible participants. On the phone, draw with a finger in the signature box, use Clear signature if necessary, review the saved record details and confirm that it is your own signature, then Save signature. Cancel discards the drawing. A network connection is required. This is not a new mandatory step in creating, progressing or closing a record.

Observations allow the reporter, assigned manager and explicitly addressed CEO recipient to sign. Tasks allow their direct assigner and assignee. Other authorized record readers can see the retained evidence, without signing on someone else's behalf. Anonymous clients have no access. Identity and the timestamp are determined by the server, not entered by the client.

The signature records normalized vector strokes, the signer name at signing, an optional note and an immutable snapshot/hash of saved record details. Observation snapshots include text, status, routing/context, resolution/disposition and photo references. Task snapshots include text, status/progress, due date/context, required checklist and latest saved non-chat activity. Chats and photo-file contents are separate evidence. Signature snapshots do not change when the record changes; the UI identifies older signed versions and permits a new signature on a new version. No signature image is reused from a personnel profile.

The server rejects a stale expected record hash, blank/dot/malformed/oversized drawings, missing explicit confirmation and account mismatches. Request UUIDs deduplicate uncertain retries; the same person cannot duplicate their signature on the same saved version. Authenticated clients have no direct insert/update/delete grants on the signature table. Existing record visibility predicates protect reads through RLS. New public APIs are invokers of permission-checked private implementations with explicit grants.

Participants receive an in-app notification. Signatures do not approve/complete work, change a status, accept an observation into AI memory, clear chats or mutate task progress cursors. Task progress and completion controls remain separate. Stored acknowledgments are a product feature; no certified digital-signature or identity-verification claim is made.

The pad uses Pointer Events and pointer capture, single-pointer drawing, cancel handling and touch-action:none within the pad. SVG vector geometry keeps a consistent 2:1 ratio on phone, rotation, desktop and stored preview. Clear/Cancel/Save controls remain outside the drawing region. Active drawing protects against app auto-updates and accidental record close; unsaved drawings exist only in memory until saved.

Validation: recordSignatures.test.mjs tests normalized finger geometry, blank/invalid inputs, direct pointer capture/cancellation, optional controls, consent, submitted identity/version and read-only evidence. record_signatures.sql runs in BEGIN/ROLLBACK, exercising own/reviewer signatures, timestamps/snapshots, stale versions, retry idempotence, unchanged observation/task/AI state, chat independence, notifications, cross-account/outsider denial and immutable client permissions. No real signature is created by tests. Real iPhone/Android finger interaction still needs on-device acceptance.
